# Spec: 운영자 비밀번호

Status: ready-for-agent

## Problem Statement

지금은 링크만 알면 누구나 투표(Poll)를 만들 수 있어서, 동아리와 상관없는 사람이나 장난으로 만든 투표가 목록을 어지럽힐 수 있다. 동아리 운영진만 투표를 올리고, 구성원은 지금처럼 가볍게 투표하고 결과를 보기를 원한다. 수업 배포 가이드도 운영자 비밀번호를 환경변수 `ADMIN_TOKEN`(값 `Artificial`)으로 등록하도록 안내한다.

## Solution

운영자(Operator)만 투표를 만들 수 있게 한다. 운영자는 `/login`에서 운영자 비밀번호(Operator Password)를 입력해 로그인하고, 브라우저를 닫을 때까지 운영자로 인정된다. 상단의 "나가기"로 언제든 로그아웃한다. 로그인하지 않은 사람은 투표 만들기 화면에 들어가면 로그인 화면으로 보내지고, API로 직접 만들려 해도 서버가 401로 거부한다. 투표하기와 결과 보기는 지금처럼 누구나 로그인 없이 쓴다.

## User Stories

### 로그인
1. 운영자로서, `/login`에서 운영자 비밀번호를 입력해 로그인하고 싶다. 그래야 투표를 만들 수 있다.
2. 운영자로서, 비밀번호가 틀리면 "비밀번호가 올바르지 않습니다."를 보고 로그인 화면에 머물고 싶다.
3. 운영자로서, 빈 비밀번호로 제출하면 "비밀번호를 입력해 주세요."를 보고 싶다.
4. 운영자로서, 로그인에 성공하면 원래 가려던 화면(예: 투표 만들기)으로 돌아가고, 따로 가려던 곳이 없으면 목록으로 가고 싶다.
5. 운영자로서, 비밀번호 입력칸의 글자가 가려지기를 원한다.
6. 운영자로서, 브라우저를 닫으면 로그인이 풀리기를 원한다. 그래야 공용 컴퓨터에 운영자 권한이 남지 않는다.
7. 운영 관점에서, 로그인 뒤 돌아갈 주소로 외부 사이트가 지정되면 무시하고 목록으로 보내기를 원한다(오픈 리다이렉트 방지).

### 상단 메뉴와 나가기
8. 누구나, 로그인하지 않았을 때 상단에서 "운영자 로그인" 링크를 보고 싶다.
9. 운영자로서, 로그인했을 때 상단에서 "투표 만들기"와 "나가기"를 보고 싶다.
10. 운영자로서, "나가기"를 누르면 로그아웃되고 목록으로 돌아가며 상단이 로그인 전 상태로 바뀌기를 원한다.

### 투표 만들기 보호
11. 운영 관점에서, 로그인하지 않은 사람이 투표 만들기 화면에 들어가면 로그인 화면으로 보내지기를 원한다.
12. 운영 관점에서, 로그인하지 않은 채 투표 만들기 API를 직접 호출하면 401로 거부되고 아무것도 저장되지 않기를 원한다. 그래야 화면을 우회해도 막힌다.
13. 운영 관점에서, 운영자 비밀번호 환경변수가 설정되지 않았으면 아무도 로그인할 수 없기를 원한다(빈 비밀번호로 뚫리지 않음).
14. 운영 관점에서, 운영자 비밀번호를 바꾸면 기존에 로그인한 모든 브라우저의 운영자 세션이 무효가 되기를 원한다.

### 기존 기능 유지
15. 투표자로서, 로그인 없이 지금처럼 목록을 보고, 표를 던지고, 결과를 보고 싶다.
16. 운영자로서, 로그인한 상태에서 지금처럼 마감 시각을 포함해 투표를 만들고 싶다.

## Implementation Decisions

- **용어**: CONTEXT.md의 운영자(Operator), 운영자 비밀번호(Operator Password). 환경변수 이름만 수업 가이드에 맞춰 `ADMIN_TOKEN`.
- **ADR**: ADR-0003(공유 비밀번호 + 브라우저 세션 쿠키), ADR-0001(투표자 익명·중복 허용은 유지), ADR-0002(raw SQL — 이번엔 DB 변경 없음).
- **운영자 세션 모듈(깊은 모듈 하나)**: 비밀번호 확인, 세션 쿠키 값 만들기·검증, 현재 요청이 운영자인지 판단을 한곳에 모은다. 인터페이스:
  - 비밀번호가 맞는가(입력 문자열) → boolean. `ADMIN_TOKEN`이 비어 있으면 항상 false. 비교는 해시 후 상수 시간 비교.
  - 현재 요청이 운영자인가() → boolean (요청 쿠키를 읽음)
  - 로그인 쿠키 설정 / 삭제
  - 돌아갈 주소 정리(입력) → `/`로 시작하고 `//`로 시작하지 않는 경로만 허용, 아니면 `/`
- **세션 쿠키**: 이름 하나, 값은 비밀번호 자체가 아니라 `ADMIN_TOKEN`으로 만든 HMAC-SHA256 서명값. `expires`/`maxAge` 없음(세션 쿠키), `httpOnly`, `sameSite: lax`, 프로덕션에서 `secure`, `path: /`. 검증은 같은 값을 다시 계산해 상수 시간 비교 → 비밀번호를 바꾸면 기존 쿠키가 모두 무효.
- **API (Route Handlers, JSON)**
  - `POST /api/operator/login` body `{ password: string }` → 200(쿠키 설정) / 400(빈 값·형식 오류) / 401(틀림)
  - `POST /api/operator/logout` → 200(쿠키 삭제)
  - `POST /api/polls` → 운영자가 아니면 401 `{ error: "운영자 로그인이 필요합니다." }`. 나머지 동작은 기존과 같다.
  - `GET /api/polls/[id]`, `POST /api/polls/[id]/vote`는 변경 없음(공개).
- **페이지**
  - `/login`: 비밀번호 폼. `next` 검색 파라미터로 돌아갈 주소를 받는다. 성공 시 그 주소로 이동하고 화면을 새로 그려 상단 메뉴를 갱신한다.
  - `/new`: 서버에서 운영자가 아니면 `/login?next=/new`로 리다이렉트.
  - 공통 레이아웃 상단: 운영자면 "투표 만들기" + "나가기", 아니면 "운영자 로그인". 첫 화면의 "아직 투표가 없습니다" 옆 만들기 링크도 운영자일 때만.
- **Next.js 버전 주의**: `cookies()`는 async, 쓰기는 Route Handler에서. 구현 전 `node_modules/next/dist/docs/`의 cookies, redirect 문서를 따른다.

## Testing Decisions

- **테스트 경계는 그대로 Playwright E2E 하나.**
- **로그인 상태 준비**: 테스트 실행 시 먼저 setup 단계가 `/api/operator/login`으로 로그인해 저장 상태(storage state)를 파일로 남기고, 기본 테스트는 그 상태(운영자)로 돈다. 로그인하지 않은 사람의 동작은 해당 테스트에서 빈 저장 상태로 덮어써 검증한다.
- **비밀번호**: 테스트와 로컬 서버 모두 `.env.local`의 `ADMIN_TOKEN`을 쓴다. 테스트 코드에 비밀번호를 하드코딩하지 않는다.
- **시나리오**: 로그인 전 상단 메뉴; 틀린 비밀번호·빈 비밀번호; 로그인 성공 후 상단 메뉴와 이동(기본 `/`, `next` 있으면 그곳); 외부 주소 `next` 무시; 세션 쿠키 속성(만료 없음·httpOnly); 나가기; 비로그인 `/new` → 로그인 → `/new` 복귀; 비로그인 `POST /api/polls` 401 및 미저장; 로그인 API 400/401/200; 비로그인 투표자의 표 던지기·결과 보기 유지; 기존 테스트 전부 통과.
- **자동 테스트하지 않는 것**: `ADMIN_TOKEN` 미설정 시 로그인 불가(스토리 13)와 비밀번호 변경 시 세션 무효(스토리 14)는 서버 환경변수를 바꿔야 해서 E2E로 다루지 않고, 운영자 세션 모듈의 설계(빈 값이면 false, 서명값 재계산 비교)로 보장한다.

## Out of Scope

- 운영자의 투표 삭제·수정 (필요하면 별도 기능으로)
- 운영자 개인 계정, 회원가입, 비밀번호 변경 화면
- 로그인 시도 횟수 제한
- 투표자 로그인·중복 투표 방지
