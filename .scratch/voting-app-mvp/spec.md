# Spec: 투표 앱 MVP

Status: ready-for-agent

## Problem Statement

동아리 회장은 동아리원들에게 간단한 결정(점심 메뉴, MT 날짜 등)을 물어볼 방법이 필요하다. 지금은 단톡방에서 손을 들게 하거나 댓글로 세는 식이라 누가 무엇을 골랐는지 세기 번거롭고, 결과를 한눈에 보기 어렵다. 로그인이나 설치 없이 링크 하나로 질문을 올리고, 구성원이 선택지 하나를 골라 투표하고, 결과를 바로 볼 수 있는 도구가 없다.

## Solution

로그인 없이 쓰는 웹 투표 앱을 만든다. 누구나 질문 하나와 선택지 2~5개로 투표(Poll)를 만든다. 투표자(Voter)는 목록에서 투표를 골라 선택지(Option) 하나에 표(Vote)를 던진다. 표를 던지면 바로 그 투표의 결과(Results)가 선택지별 득표수와 퍼센트 숫자 리스트로 보인다. 결과는 투표하지 않은 사람도 언제든 볼 수 있다.

## User Stories

### 투표 만들기
1. 투표를 올리는 사람으로서, 로그인 없이 투표를 만들고 싶다. 그래야 계정 없이 바로 구성원에게 물어볼 수 있다.
2. 투표를 올리는 사람으로서, 질문을 한 줄 입력하고 싶다. 그래야 무엇을 묻는지 구성원이 알 수 있다.
3. 투표를 올리는 사람으로서, 폼이 처음 열릴 때 선택지 입력칸 2개가 준비되어 있기를 원한다. 그래야 가장 흔한 양자택일을 바로 만들 수 있다.
4. 투표를 올리는 사람으로서, 선택지 입력칸을 최대 5개까지 추가하고 싶다. 그래야 여러 후보를 물어볼 수 있다.
5. 투표를 올리는 사람으로서, 선택지 입력칸을 지울 수 있기를 원한다(단 2개 미만으로는 줄어들지 않음). 그래야 실수로 추가한 칸을 없앨 수 있다.
6. 투표를 올리는 사람으로서, 선택지가 5개일 때 추가 버튼이 막히기를 원한다. 그래야 규칙을 넘는 투표를 만들려다 실패하지 않는다.
7. 투표를 올리는 사람으로서, 질문이 비어 있거나 공백뿐이면 제출이 거부되고 이유를 보고 싶다. 그래야 빈 투표가 올라가지 않는다.
8. 투표를 올리는 사람으로서, 선택지가 비어 있거나 공백뿐이면 제출이 거부되고 이유를 보고 싶다.
9. 투표를 올리는 사람으로서, 같은 이름의 선택지를 두 번 넣으면(앞뒤 공백 제거 후 비교) 제출이 거부되고 이유를 보고 싶다. 그래야 결과가 헷갈리지 않는다.
10. 투표를 올리는 사람으로서, 입력 앞뒤의 공백이 자동으로 제거되어 저장되기를 원한다.
11. 투표를 올리는 사람으로서, 투표를 만든 직후 그 투표의 투표하기 화면으로 이동하고 싶다. 그래야 주소를 복사해 구성원에게 공유할 수 있다.
12. 투표를 올리는 사람으로서, 입력한 선택지 순서가 투표하기와 결과 화면에서도 그대로 유지되기를 원한다.

### 투표 목록
13. 투표자로서, 첫 화면에서 모든 투표를 최신순으로 보고 싶다. 그래야 최근 질문을 먼저 찾을 수 있다.
14. 투표자로서, 목록의 각 투표에서 질문을 보고 "투표하기"와 "결과 보기"로 바로 이동하고 싶다.
15. 투표자로서, 투표가 하나도 없을 때 "아직 투표가 없습니다"와 투표 만들기 링크를 보고 싶다.
16. 누구나, 첫 화면에서 "투표 만들기"로 이동할 수 있기를 원한다.

### 표 던지기
17. 투표자로서, 로그인 없이 표를 던지고 싶다.
18. 투표자로서, 투표하기 화면에서 질문과 모든 선택지를 보고 싶다.
19. 투표자로서, 선택지 중 정확히 하나만 고를 수 있기를 원한다.
20. 투표자로서, 아무것도 고르지 않고 제출하면 안내를 받고 싶다.
21. 투표자로서, 표를 제출하면 곧바로 그 투표의 결과 화면으로 이동하고 싶다.
22. 투표자로서, 투표하기 화면에서 투표하지 않고도 결과 화면으로 갈 수 있기를 원한다.
23. 투표자로서, 없는 투표 주소로 들어가면 "투표를 찾을 수 없습니다" 화면을 보고 싶다.
24. 투표자로서, 여러 사람이 동시에 투표해도 표가 하나도 사라지지 않기를 원한다.

### 결과 보기
25. 누구나, 투표 여부와 상관없이 언제든 결과를 볼 수 있기를 원한다.
26. 누구나, 결과 화면에서 질문과 선택지별 득표수를 보고 싶다.
27. 누구나, 선택지별 득표 퍼센트(정수 반올림)를 보고 싶다.
28. 누구나, 전체 표 수를 보고 싶다.
29. 누구나, 표가 0개인 투표의 결과에서도 화면이 깨지지 않고 "아직 투표가 없습니다"와 모든 선택지 0표·0%를 보고 싶다.
30. 누구나, 결과 화면에서 투표하기 화면과 목록으로 돌아갈 수 있기를 원한다.
31. 누구나, 없는 투표의 결과 주소로 들어가면 "투표를 찾을 수 없습니다" 화면을 보고 싶다.

### 서버 규칙
32. 운영 관점에서, 폼을 거치지 않고 API를 직접 호출해도 질문·선택지 규칙(빈칸, 중복, 2~5개)이 서버에서 똑같이 거부되기를 원한다. 그래야 클라이언트 검사를 우회한 잘못된 투표가 저장되지 않는다.
33. 운영 관점에서, 다른 투표의 선택지 ID나 존재하지 않는 선택지 ID로 표를 던지면 거부되기를 원한다.

## Implementation Decisions

- **용어**: `CONTEXT.md`의 투표(Poll), 선택지(Option), 표(Vote), 투표자(Voter), 결과(Results)를 코드·UI·테스트 이름에 그대로 쓴다. 화면 문구는 한국어.
- **ADR 준수**: ADR-0001(로그인 없는 익명 투표, 중복 투표 방지 없음, 투표 수정·삭제 없음), ADR-0002(ORM 없이 `@neondatabase/serverless`로 raw SQL).
- **스키마**: 두 테이블. 표는 익명이고 중복 방지가 없으므로 별도 표 테이블 없이 선택지의 득표수 카운터로 기록한다. 선택지 순서를 보장하기 위해 `position`을 둔다.

  ```sql
  create table polls (
    id uuid primary key default gen_random_uuid(),
    question text not null,
    created_at timestamptz not null default now()
  );

  create table options (
    id uuid primary key default gen_random_uuid(),
    poll_id uuid not null references polls(id) on delete cascade,
    label text not null,
    position integer not null,
    vote_count integer not null default 0,
    unique (poll_id, position)
  );
  ```

  스키마 SQL은 저장소에 파일로 남기고, 사람이 Neon SQL Editor에서 직접 실행한다.
- **DB 연결**: `DATABASE_URL` 환경변수(`.env.local`)만 사용. 코드에 연결 문자열을 쓰지 않는다.
- **투표 데이터 모듈(깊은 모듈 하나)**: 모든 SQL과 규칙을 한 모듈에 모은다. 페이지와 API는 이 모듈만 호출한다. 인터페이스:
  - 투표 목록 조회(최신순, 질문과 id)
  - 투표 만들기(질문, 선택지 라벨 목록) → 새 투표 id, 또는 검증 오류
  - 투표 하나 조회(질문 + 순서대로 정렬된 선택지) → 없으면 "없음"
  - 표 던지기(투표 id, 선택지 id) → 성공, 또는 "투표 없음" / "선택지가 이 투표에 속하지 않음"
  - 결과 조회(투표 id) → 선택지별 득표수·퍼센트, 전체 표 수, 또는 "없음"
- **검증 규칙**(서버가 기준, 폼도 같은 규칙으로 미리 안내): 질문·선택지 앞뒤 공백 제거 후 빈 값 불가, 같은 투표 안 선택지 라벨 중복 불가(공백 제거 후 비교), 선택지 2~5개.
- **투표 만들기**는 투표와 선택지 저장이 한 번에 성공하거나 한 번에 실패해야 한다(선택지 없는 투표가 남으면 안 됨).
- **표 던지기**는 해당 선택지의 득표수를 DB 안에서 원자적으로 1 증가시킨다(`vote_count = vote_count + 1`, 선택지 id와 투표 id가 모두 일치하는 행에만). 읽고-더하고-쓰는 방식 금지. 영향받은 행이 없으면 거부.
- **퍼센트**: 선택지 득표수 / 전체 표 수 × 100을 정수로 반올림. 전체 표가 0이면 모두 0%. 반올림 때문에 합이 100이 아닐 수 있음을 허용한다.
- **페이지**
  - `/` 투표 목록
  - `/new` 투표 만들기 폼
  - `/polls/[id]` 투표하기
  - `/polls/[id]/results` 결과(숫자 리스트)
  - 목록·투표하기·결과 페이지는 서버에서 투표 데이터 모듈을 직접 호출해 렌더링한다. 없는 투표면 Not Found 화면.
- **API (Route Handlers, JSON)**
  - `POST /api/polls` body `{ question: string, options: string[] }` → 201 `{ id }` / 400 `{ error }`
  - `GET /api/polls/[id]` → 200 `{ id, question, createdAt, options: [{ id, label }] }` / 404
  - `POST /api/polls/[id]/vote` body `{ optionId: string }` → 200 / 400(선택지 불일치·형식 오류) / 404(투표 없음)
  - 잘못된 형식의 id(uuid 아님)는 DB 오류가 아니라 404로 처리한다.
- **폼 동작**: 투표 만들기·표 던지기 폼은 위 API를 호출하고, 성공하면 각각 투표하기 화면·결과 화면으로 이동한다. 서버가 돌려준 오류 문구를 폼에 보여준다.
- **Next.js 버전 주의**: 이 저장소의 Next.js는 학습 데이터와 다를 수 있으므로, 구현 전 `node_modules/next/dist/docs/`의 해당 가이드(App Router, Route Handlers, 동적 params 등)를 읽고 따른다.

## Testing Decisions

- **테스트 경계는 하나: Playwright E2E.** 실제 브라우저로 `next dev`(또는 빌드된 앱)를 띄워 사용자가 하는 그대로 검증한다. 내부 함수·SQL·컴포넌트 구조는 테스트하지 않는다. 겉으로 보이는 동작(화면 문구, 이동, 득표수)만 검증해서 내부를 바꿔도 테스트가 깨지지 않게 한다.
- **서버 규칙 검증**은 같은 Playwright의 요청(request) 기능으로 API를 직접 호출해 확인한다(유저 스토리 32, 33). 별도 테스트 도구를 추가하지 않는다.
- **DB**: 개발용 Neon DB(`.env.local`의 `DATABASE_URL`)를 공유한다. 각 테스트는 자기가 쓸 투표를 직접 만들고, 끝나면 자기가 만든 투표를 삭제해 정리한다(선택지는 cascade로 함께 삭제). 다른 테스트나 기존 데이터에 의존하지 않으며, 식별하기 쉬운 고유 질문 문구(예: 테스트 접두어 + 랜덤값)를 쓴다. 정리용 삭제는 테스트 코드에서 DB에 직접 실행한다(앱에는 삭제 기능이 없음, ADR-0001).
- **"목록이 비었을 때" 문구**(유저 스토리 15)는 공유 DB라 E2E로 안정적으로 재현할 수 없으므로 자동 테스트하지 않고 수동 확인한다.
- **다뤄야 할 시나리오**: 투표 만들기 정상 흐름 → 투표하기 화면 이동, 선택지 입력칸 추가/삭제와 2·5개 한계, 폼 검증 오류(빈 질문, 빈 선택지, 중복 선택지), 목록에 새 투표가 최신순 맨 위 근처에 표시, 표 던지기 → 결과 이동 및 득표수 1 증가, 아무것도 안 고르고 제출, 결과 0표 상태, 퍼센트 반올림, 선택지 순서 유지, 없는 투표 404(잘못된 uuid 포함), API 직접 호출 시 검증 거부, 다른 투표 선택지로 표 던지기 거부, 동시 표 여러 개가 모두 반영.
- **선행 사례**: 저장소에 기존 테스트가 없다. 이 스펙에서 Playwright 설정과 `npm run test` 스크립트를 새로 만든다.

## Out of Scope

- 투표 마감 시간 — 부록 실습에서 추가 예정
- 결과 그래프 — 부록 실습에서 추가 예정. 이번엔 숫자 리스트만
- 화면에 학생 본인 이름 표시 — 요구사항의 정확한 의미를 확인한 뒤 별도로 추가
- 로그인, 운영자 인증, 투표자 신원 확인
- 중복 투표 방지(쿠키 포함)
- 투표·선택지 수정과 삭제
- 복수 선택
- 페이지 나누기, 검색, 결과 실시간 갱신
- Vercel 배포(수업자료 부록 가이드를 따로 따름)

## Further Notes

- 이 앱은 부록 실습에서 마감 시간과 그래프가 덧붙여질 출발점이다. 결과 계산(득표수·퍼센트·전체 표 수)을 투표 데이터 모듈에 모아 두면 그래프 교체 시 화면만 바꾸면 된다.
- 스키마는 사람이 Neon SQL Editor에서 실행해야 테이블이 생긴다. 첫 번째 구현 티켓의 완료 조건에 이 단계를 포함한다.
