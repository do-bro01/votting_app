# Spec: 입장 비밀번호로 앱 전체 막기

Status: ready-for-agent

## Problem Statement

지금은 투표 만들기·삭제만 비밀번호로 막혀 있어서, 동아리 밖의 사람도 링크만 알면 투표 목록과 질문을 보고, 표를 던지고, 결과를 볼 수 있다. 동아리는 이 앱을 "우리끼리만" 쓰고 싶다. 비밀번호를 모르는 사람은 앱의 어떤 화면도 보지 못해야 한다.

## Solution

앱 전체를 입장 비밀번호(Entry Password) 하나로 막는다. 비밀번호를 입력하지 않은 사람이 어느 주소로 들어오든 입장 화면이 먼저 나오고, 입력하면 원래 열려던 화면으로 간다. 들어온 사람은 모두 구성원(Member)으로서 같은 권한을 가진다: 투표 만들기·삭제, 표 던지기, 결과 보기. 모든 API도 구성원이 아니면 401로 거부한다. 입장은 브라우저를 닫을 때까지 유지되고 "나가기"로 끝낸다. 비밀번호는 지금과 같은 환경변수 `ADMIN_TOKEN`이다(ADR-0004).

## User Stories

### 입장
1. 비밀번호를 모르는 사람으로서, 앱 주소(`/`)로 들어오면 입장 화면만 보고 투표 목록은 볼 수 없어야 한다.
2. 비밀번호를 모르는 사람으로서, 공유받은 투표하기 주소(`/polls/…`)로 들어와도 입장 화면이 먼저 나와야 한다.
3. 비밀번호를 모르는 사람으로서, 결과 주소(`/polls/…/results`)로 들어와도 입장 화면이 먼저 나와야 한다.
4. 비밀번호를 모르는 사람으로서, 투표 만들기 주소(`/new`)로 들어와도 입장 화면이 먼저 나와야 한다.
5. 구성원으로서, 입장 화면에서 비밀번호를 입력하면 원래 열려던 화면(검색 파라미터 포함)으로 가고 싶다. 따로 열려던 곳이 없으면 목록으로 간다.
6. 구성원으로서, 비밀번호가 틀리면 "비밀번호가 올바르지 않습니다.", 비어 있으면 "비밀번호를 입력해 주세요."를 보고 입장 화면에 머물고 싶다.
7. 구성원으로서, 비밀번호 입력칸의 글자가 가려지기를 원한다.
8. 구성원으로서, 브라우저를 닫으면 입장이 풀리기를 원한다.
9. 운영 관점에서, 돌아갈 주소로 외부 사이트가 지정되면 무시하고 목록으로 보내기를 원한다.
10. 누구나, 입장 화면에서도 하단의 만든 사람 이름을 보고 싶다.
11. 입장하지 않은 사람으로서, 입장 화면 상단에 "투표 만들기"·"나가기"가 보이지 않아야 한다.

### 구성원의 권한
12. 구성원으로서, 입장한 뒤 목록·투표하기·결과·투표 만들기를 모두 쓰고 싶다.
13. 구성원으로서, 투표하기 화면에서 "투표 삭제"로 확인 단계를 거쳐 투표를 지우고 싶다(구성원이면 누구나).
14. 구성원으로서, 상단의 "나가기"를 누르면 입장이 끝나고 입장 화면으로 돌아가기를 원한다.
15. 구성원으로서, 나간 뒤 뒤로 가기나 주소 입력으로 목록·투표 화면에 다시 들어가려 하면 입장 화면이 나와야 한다.

### API
16. 운영 관점에서, 입장하지 않은 채 투표 조회·만들기·삭제·표 던지기 API를 부르면 모두 401이고 아무것도 바뀌지 않기를 원한다.
17. 운영 관점에서, 입장 API(`/api/login`)는 입장하지 않아도 부를 수 있어야 한다.

## Implementation Decisions

- **용어**: CONTEXT.md의 구성원(Member), 입장 비밀번호(Entry Password). 코드·API 경로·화면 문구에서 "운영자(operator)"를 모두 걷어낸다. 환경변수 이름 `ADMIN_TOKEN`만 수업 가이드에 맞춰 그대로 둔다.
- **ADR**: ADR-0004(앱 전체 입장 비밀번호, 모두 같은 권한; ADR-0003 대체), ADR-0001(표 익명·중복 허용·수정 불가 유지), ADR-0002(raw SQL, DB 변경 없음).
- **모듈 나누기**
  - 입장 서명 모듈(순수, `next/headers`에 의존하지 않음): 쿠키 이름, 비밀번호가 맞는가, 쿠키 값이 유효한 입장 서명인가. Proxy와 서버 코드가 함께 쓴다. `ADMIN_TOKEN`이 비어 있으면 항상 false. 비교는 해시 후 상수 시간.
  - 입장 세션 모듈(server-only): 현재 요청이 구성원인가, 입장 쿠키 설정·삭제, 구성원 전용 API 앞의 401 가드, 돌아갈 주소 정리(URL 파싱 후 출처 확인).
- **Proxy(`proxy.ts`)**: 정적 파일(`_next/static`, `_next/image`, `favicon.ico`)과 입장 화면(`/login`), 입장·나가기 API(`/api/login`, `/api/logout`)를 뺀 모든 요청에서 입장 쿠키를 확인한다. 구성원이 아니면 화면 요청은 `/login?next=<원래 경로+검색 파라미터>`로 리다이렉트, `/api/*`는 401 `{ error: "비밀번호를 입력해 주세요." }`.
- **Route Handler 재확인**: 투표 조회·만들기·삭제·표 던지기 API는 Proxy와 별개로 각 Handler에서도 구성원인지 확인해 401을 돌려준다(Proxy matcher가 바뀌어도 뚫리지 않게).
- **API 경로 변경**: `/api/operator/login` → `/api/login`, `/api/operator/logout` → `/api/logout`. 요청·응답 형식과 상태 코드(400/401/200)는 그대로.
- **화면**
  - `/login`: 제목 "투표 앱", 안내 "비밀번호를 입력해야 들어갈 수 있습니다.", 입력칸 라벨 "입장 비밀번호", 버튼 "입장". 성공 시 돌아갈 주소로 이동 후 새로 그린다.
  - 상단: 구성원이면 "투표 만들기" + "나가기", 아니면 앱 이름만.
  - "나가기" → 입장 쿠키 삭제 후 `/`로 이동 → Proxy가 입장 화면으로 보낸다.
  - 투표하기 화면의 "투표 삭제"는 구성원 모두에게 보인다.
  - `/new`, 첫 화면의 페이지별 운영자 확인 코드는 Proxy로 대체되므로 제거한다.

## Testing Decisions

- **테스트 경계는 그대로 Playwright E2E 하나.** 기본 테스트는 setup 단계에서 입장한 저장 상태(구성원)로 돈다. 입장 전 동작은 빈 저장 상태로 덮어써 검증한다. 비밀번호는 `.env.local`의 `ADMIN_TOKEN`에서 읽는다.
- **시나리오**: 입장 전 `/`, `/new`, `/polls/<id>`, `/polls/<id>/results`가 모두 입장 화면으로 가고 목록·질문 텍스트가 보이지 않음; 입장 후 원래 주소(검색 파라미터 포함)로 복귀; 틀린·빈 비밀번호; password 입력칸; 외부 주소 무시(탭 우회 포함); 세션 쿠키 속성; 입장 화면 상단에 메뉴 없음, 하단 이름 있음; 나가기 후 입장 화면, 다시 `/` 들어가면 입장 화면; 입장 전 모든 API 401과 미변경(만들기 미저장, 표 미반영, 삭제 안 됨); 입장 API는 입장 전에도 동작; 구성원의 삭제 버튼; 기존 기능 테스트 전부 통과.
- `ADMIN_TOKEN` 미설정·변경 시 동작은 입장 서명 모듈의 설계로 보장하고 E2E로 다루지 않는다(ADR-0003과 동일).

## Out of Scope

- 구성원용·운영자용 비밀번호 분리, 개인 계정
- 투표 수정, 로그인 시도 횟수 제한
- 누가 투표했는지 기록, 중복 투표 방지

## Further Notes

- Vercel의 `ADMIN_TOKEN`은 이미 등록되어 있다면 그대로 쓴다. 배포 후 기존 운영자 쿠키는 API 경로·쿠키 이름이 바뀌어 무효가 되므로 한 번 다시 입장해야 한다.
